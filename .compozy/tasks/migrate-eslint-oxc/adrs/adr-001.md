# ADR-001: Replace ESLint with OXC (Oxlint) as the Project Linter

## Status

Accepted

## Date

2026-05-29

## Context

The project currently uses ESLint v9 flat config (`eslint.config.ts`, 331 lines) with 12 plugins and a custom local plugin. OXC (Oxlint) is 50–100x faster than ESLint, has built-in Rust-native implementations of most ESLint plugins used, and reduces dependency weight. The project already uses Prettier for formatting; OXC replaces only linting. A full comparison was documented in project memory.

The user chose a direct replacement approach: OXC replaces ESLint in the same turbo pipeline, pre-commit hooks, and CI workflows, with no transitional dual-run phase.

## Decision

Replace ESLint with OXC (Oxlint) as the single linter for the project:

- Install `oxlint` as a root devDependency
- Convert `eslint.config.ts` to `.oxlintrc.json` using `@oxlint/migrate`, then manually refine
- Update all `lint` and `lint:fix` scripts in every app/package to call `oxlint` instead of `eslint`
- Update turbo.json global dependencies to reference `.oxlintrc.json` instead of `eslint.config.ts`
- Update lint-staged and pre-commit hooks to run `oxlint --fix`
- Remove all ESLint dependencies from root `package.json`
- Remove the `eslint.config.ts` file
- Keep Prettier for formatting (unchanged)

## Alternatives Considered

### Alternative 1: Run ESLint + OXC in parallel (transitional)

- **Description**: Add OXC alongside ESLint for a period, using `eslint-plugin-oxlint` to disable overlapping ESLint rules.
- **Pros**: Safer rollback; CI catches regressions in OXC coverage vs ESLint.
- **Cons**: Dual dependency weight; longer migration window; CI time does not improve until ESLint is removed.
- **Why rejected**: User chose direct replacement. OXC coverage of the plugins used is sufficient for cutover.

### Alternative 2: Biome

- **Description**: Replace ESLint + Prettier with Biome (all-in-one formatter + linter in Rust).
- **Pros**: Single tool; simpler toolchain.
- **Cons**: Biome v2 does not support JS plugins — the custom `@job-tracker/eslint-plugin` would have no migration path. Biome's type inference is incomplete vs OXC's TypeScript 7 integration.
- **Why rejected**: Custom plugin incompatibility; user's earlier comparison concluded OXC is the only viable candidate.

## Consequences

### Positive

- 50–100x faster linting in CI and local runs
- Reduced dependency tree (remove ~15 ESLint packages)
- Built-in TS type-aware linting via TypeScript 7 (tsgo)
- Simpler config file (`.oxlintrc.json` vs 331-line flat config)
- Native multi-file analysis for cross-module rules

### Negative

- Some ESLint-specific rules may not have 1:1 OXC equivalents — must audit and adjust
- Custom `@job-tracker/eslint-plugin` must be rewritten as a Rust plugin (see ADR-002)
- Team must learn OXC config format and rule naming

### Risks

- React Compiler rules not natively supported — may need JS plugin or alternative approach
- `eslint-plugin-testing-library` and `eslint-plugin-better-tailwindcss` not natively available — see ADR-004 for plugin mapping
