# TechSpec: Migrate ESLint to OXC (Oxlint)

**Feature slug:** `migrate-eslint-oxc`  
**PRD:** None — infra-only change

## Executive Summary

Replace ESLint v9 (flat config, 331 lines, 12 plugins, 1 custom plugin) with OXC (Oxlint) as the project's single linter. OXC is 50–100x faster than ESLint, natively supports most plugins used, and eliminates ~15 ESLint dependencies. Prettier remains for formatting. Migrate progressively by app (api → web → ui → extension), rewriting the 2 custom ESLint rules as OXC Rust plugins and mapping all existing plugins to native or JS Plugin equivalents.

**Primary trade-off:** Rewriting 2 custom rules as Rust plugins requires Rust development effort and OXC plugin API familiarity, in exchange for eliminating ESLint entirely and gaining native-speed rule execution.

```
│                    Before (ESLint)                          │
│                                                             │

│  ├── typescript-eslint                                      │

│  ├── @next/eslint-plugin-next                               │
│  ├── eslint-plugin-testing-library                          │

                            │ replace

│  packages/oxlint-plugin/ (Rust crate)                       │
└─────────────────────────────────────────────────────────────┘
```

| Component                 | Responsibility                                                      |
| ------------------------- | ------------------------------------------------------------------- |
| `.oxlintrc.json`          | Single config file — plugins, rules, categories, overrides, globals |
| `oxlint` CLI              | Lint runner — replaces `eslint` in all scripts                      |
| `packages/oxlint-plugin/` | Rust crate with 2 custom rules (replaces `packages/eslint-plugin/`) |
| `packages/eslint-plugin/` | **Removed** after migration                                         |
| `eslint.config.ts`        | **Removed** after migration                                         |
| `scripts/fix-imports.ts`  | **Removed** — sorting handled by OXC import plugin                  |

## Testing Approach

### Verification Per App

Each app migration step validates:

| Check                             | Command                                       |
| --------------------------------- | --------------------------------------------- |
| Lint passes with zero warnings    | `oxlint . --max-warnings=0 --no-warn-ignored` |
| Existing lint violations resolved | Compare `oxlint` vs baseline `eslint` output  |
| TypeScript typecheck              | `tsc --noEmit`                                |
| Tests pass                        | `pnpm --filter <app> run test`                |

### Migration Validation

| Scenario                                      | Expected                                         |
| --------------------------------------------- | ------------------------------------------------ |
| `oxlint` on all files                         | Zero errors, zero warnings at `--max-warnings=0` |
| `oxlint --fix` produces no diff on clean code | Idempotent fix application                       |
| Import sort order matches current convention  | Diff review of sorted files                      |
| Custom rules fire on known violations         | Positive test cases pass                         |
| `pnpm validate` succeeds                      | Full pipeline green                              |

### Pre-commit check

- Replace ESLint in lint-staged; run `oxlint --fix` + `prettier --write`
- Verify `lint-staged` works on staged changes

## Development Sequencing

### Build Order

0. **Install OXC + generate initial config** — `pnpm add -D oxlint`; run `npx @oxlint/migrate eslint.config.ts` to produce `.oxlintrc.json` with `--type-aware --js-plugins` flags. _Baseline step._

1. **Rewrite custom rules as Rust plugin** — Create `packages/oxlint-plugin/` with `prefer-try-run-over-try-catch` and `no-as-unknown-as`. Wire into OXC config. _Depends on 0._

2. **Migrate `apps/api`** — Apply `.oxlintrc.json` (no React/Next plugins needed). Fix any new violations. Update `api/package.json` lint script. Run typecheck + tests. _Depends on 1 (if API code triggers custom rules)._

3. **Migrate `apps/web`** — Enable `react`, `import`, `nextjs`, `jsx-a11y` plugins in config. Verify JS Plugins for react-compiler + better-tailwindcss. Update `web/package.json`. Run typecheck + tests. _Depends on 2._

4. **Migrate `packages/ui`** — Enable `react` + `import` plugins. Update `ui/package.json`. Run typecheck + tests (Storybook). _Depends on 3._

5. **Migrate `apps/extension`** — Enable `react` + `import` + JS Plugins. Update `extension/package.json`. Run typecheck + tests. _Depends on 4._

6. **Cleanup ESLint remnants** — Remove `eslint`, `eslint.config.ts`, `packages/eslint-plugin/`, `scripts/fix-imports.ts`, all ESLint dependencies from root `package.json`. Update turbo.json `globalDependencies`. Update pre-commit hooks. Update editor recommendations. _Depends on 5._

### Technical Dependencies

- `oxlint` must be compatible with current Node.js version (22.x) — verified via OXC docs (Node 18+).
- Rust toolchain required for `packages/oxlint-plugin/` compilation.

## Monitoring and Observability

- No runtime monitoring — OXC is a build-time/CI tool.
- CI `Assert clean tree after lint` remains; the diff after `oxlint --fix` must be empty.
- Track lint duration in CI before/after migration for benchmark.

## Technical Considerations

### Key Decisions

See ADRs 001–005.

### Known Risks

| Risk                                                          | Mitigation                                                                                                                    |
| ------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| OXC JS Plugins (alpha) may break on upgrade                   | Pin OXC version; test upgrade in CI before applying                                                                           |
| React Compiler rules not available as native OXC plugin       | Use community JS Plugin; verify compatibility; fallback to removing rules temporarily                                         |
| `better-tailwindcss` incompatible with OXC JS Plugin API      | Drop plugin (Tailwind class sorting is a style preference, not correctness); or write minimal Rust rule for critical patterns |
| Import sort order differs from current behavior               | Run OXC with `--fix` on the repo once, commit the diff, accept new order                                                      |
| `maxWarnings: 0` may block CI if a rule triggers unexpectedly | Use `--max-warnings=0` consistently (matches current ESLint behavior)                                                         |

### Removed Dependencies

After migration, the following packages are removed from root `devDependencies`:

- `eslint`, `@eslint/js`
- `typescript-eslint`, `@typescript-eslint/*`
- `eslint-plugin-react`, `eslint-plugin-react-hooks`, `eslint-plugin-react-compiler`, `eslint-plugin-react-refresh`
- `eslint-plugin-simple-import-sort`
- `eslint-plugin-better-tailwindcss`
- `@next/eslint-plugin-next`
- `eslint-plugin-testing-library`
- `eslint-config-prettier`
- `globals`

Plus the workspace package `packages/eslint-plugin/` and the script `scripts/fix-imports.ts`.
