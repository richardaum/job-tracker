# ADR-001: Direct Markdown Export from Actions Dropdown

## Status

Accepted

## Date

2026-06-01

## Context

Users need to export job details from the Job Details page as a Markdown file for external use (sharing, documentation, LLM context, personal archives). The Job Details page has an existing Actions dropdown in the header with items like "Fill job fields automatically", "Update status", and "Remove". The export action needs a placement that is discoverable but does not clutter the primary header area.

## Decision

Add an "Export as Markdown" item inside the existing Actions dropdown menu. On click, the frontend fetches all job data (including notes and stage events), formats it as Markdown, and triggers an immediate browser download of a `.md` file. No preview dialog — one click, one file.

## Alternatives Considered

### Alternative 1: Export with Preview Dialog

- **Description**: Before downloading, show a dialog with a preview of the generated Markdown so the user can review and optionally edit it.
- **Pros**: User has control over the output before saving.
- **Cons**: Extra friction for a utility action; most users will download without reviewing.
- **Why rejected**: Adds unnecessary UI complexity for marginal benefit. The action is a utility export, not a document editor.

### Alternative 2: API-Generated Markdown Endpoint

- **Description**: A dedicated API endpoint (REST or GraphQL) that returns the job as a Markdown string or file stream.
- **Pros**: Server-side control over format; could be reused by other clients (extension, API consumers).
- **Cons**: Requires backend development, new endpoint, deployment. The frontend already has all the data from GraphQL queries.
- **Why rejected**: Client-side generation is simpler, faster, and sufficient for this use case.

## Consequences

### Positive

- Single-click export, minimal friction.
- No backend changes required.
- Leverages existing Actions dropdown pattern.
- Export file is portable and human-readable.

### Negative

- Requires fetching notes and stage events if not already loaded (additional GraphQL queries on click).
- Markdown format is hardcoded — no customization per export.

### Risks

- Large jobs with many notes could have a slight delay while fetching data. Mitigation: show a loading state on the menu item.
- User may accidentally trigger export. Mitigation: it is one click inside a dropdown, unlikely to be accidental.

## Implementation Notes

- Client-side Markdown generation using a template function.
- Download via `URL.createObjectURL` with a `Blob` of type `text/markdown`.
- File name: `{job-title}-{company}.md` (slugified).
- Fetch job data from existing `useJobQuery`, notes from `useJobNotesQuery`, stage events from `useJobStageEventsQuery` at export time.
- Place the menu item before the separator (before "Remove") in the Actions dropdown.
