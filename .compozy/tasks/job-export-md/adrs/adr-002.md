# ADR-002: On-Demand Fetch with Export Component

## Status

Accepted

## Date

2026-06-01

## Context

The export feature needs job data, notes, and stage events. The job data is already loaded by `useJobDetailsViewModel` in `JobDetailsLayout`. Notes and stage events are fetched by individual tab pages and are not available in the layout context.

## Decision

Create a dedicated `ExportJobMdMenuItem` component that:

1. Receives the `jobId` prop.
2. On click, fetches notes and stage events via `useLazyQuery` (Apollo).
3. Uses the already-mounted job data from the layout (via a passed job object or ref).
4. Generates Markdown and triggers browser download.

The component is mounted directly in `JobDetailsLayout` inside the Actions dropdown as a layout-owned menu item.

## Alternatives Considered

### Alternative 1: Fetch Notes/Events at Layout Mount

- **Description**: Add `JobNotesQuery` and `JobStageEventsQuery` to the layout, keeping data always available.
- **Pros**: No fetch delay on export click.
- **Cons**: Wastes bandwidth on every job details page load, even when user never exports. Violates YAGNI.
- **Why rejected**: Fetch-on-demand is more efficient and follows the principle of loading what the user asks for.

### Alternative 2: Inline Logic in Layout

- **Description**: Put the fetch + generate + download logic directly in `JobDetailsLayout.tsx` as a callback.
- **Pros**: Fewer files.
- **Cons**: Violates SRP; layout is already 400 lines. Makes testing harder.
- **Why rejected**: A separate component keeps the layout clean and the export logic testable and reusable.

## Consequences

### Positive

- No fetch overhead unless user exports.
- Clean separation of concerns.
- Easy to test the Markdown generation in isolation.

### Negative

- Slight loading delay on first export click (fetch notes + events).
- Menu item needs a loading state while data is being fetched.

### Risks

- If the user has many notes, the fetch could be slow. Mitigation: show loading state; notes queries are paginated if needed in the future.

## Implementation Notes

- Use `useLazyQuery` from Apollo for `JobNotes` and `JobStageEvents`.
- Use `URL.createObjectURL(new Blob([mdString], { type: "text/markdown" }))` for download.
- File name: slugified `{title}-{company}.md`, fallback `job-{id}.md`.
- Place in `apps/web/src/modules/jobs/details/components/ExportJobMdMenuItem.tsx`.
