# ADR-005: Work Preferences Dual-Mode Component

**Status:** Accepted
**Date:** 2026-05-23

## Context

Work preferences currently exist only as a modal (`PreferencesDialog`) used in 3 places:

1. `ResumesPage` — action bar button "Work Preferences" opens the modal
2. `MatchAnalysisPage` — Actions dropdown "Work Preferences" opens the modal
3. `MatchAnalysisPage` — `MatchItemCard` opens modal in `readOnly` mode

The PRD adds a 4th use case: an inline editor rendered directly in the profile's Work Preferences tab at `/profile/preferences`.

## Decision

**Extract the form logic into a `WorkPreferencesEditor` component that supports both `inline` and `dialog` modes.**

```tsx
type WorkPreferencesEditorProps = {
  mode: "inline" | "dialog";
  readOnly?: boolean;
  onClose?: () => void; // only used in dialog mode
};
```

- `mode="inline"`: Renders the form directly in the DOM flow. Used by `/profile/preferences/page.tsx`.
- `mode="dialog"`: Renders inside a `<Dialog>` shell. Used by the existing modal consumers.
- The existing `PreferencesDialog` becomes a thin wrapper: `<Dialog><WorkPreferencesEditor mode="dialog" /></Dialog>`.
- All 3 existing modal call sites remain unchanged — they only need the wrapper import updated.

## Alternatives Considered

### B — Separate inline component

Create a new `WorkPreferencesInline` from scratch. Rejected because it duplicates the form state, validation, mutation logic, and item CRUD — two components doing the same thing with inevitable drift.

### C — Remove modal, link to profile tab

Replace all modal openings with `<Link href="/profile/preferences">`. Rejected because it removes quick access from the Resumes page and Match Analysis — users editing their resume or reviewing a match would need to navigate away and back.

## Consequences

- **Positive:** Single implementation for work preferences editing. Existing modal consumers unaffected. New inline use case supported with the same code.
- **Negative:** `PreferencesDialog` currently uses Dialog's title/description props — these must be hoisted to the wrapper. The `readOnly` prop disables editing but still shows data; must ensure this works identically in inline mode.
- **Neutral:** The component lives in `modules/work-preferences/components/` alongside the existing `PreferencesDialog`.
