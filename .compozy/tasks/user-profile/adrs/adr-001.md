# ADR-001: Unified Profile Hub

**Status:** Accepted
**Date:** 2026-05-23

## Context

The app has no user profile page. User identity (name, email, avatar) comes from Google OAuth and is read-only. App settings are planned in spec `031-product-settings-screen` as a standalone `/settings` route. Resume management lives on a separate `/resumes` route. Work preferences exist as a modal dialog scattered across multiple pages.

The user wants a single, centralized place for everything about them — identity, settings, resumes, and work preferences — accessible from the sidebar user card.

## Decision

**Create a unified `/profile` page with 4 horizontal tabs as subpages: Identity (`/profile`), Settings (`/profile/settings`), Resumes (`/profile/resumes`), Work Preferences (`/profile/preferences`).**

- Entry point: the existing sidebar user card (avatar + name + email) becomes clickable with a chevron icon and row hover effect, navigating to `/profile`.
- The "Resumes" sidebar nav item is removed; resume management moves entirely into the Profile → Resumes tab.
- The "Settings" bottom sidebar item becomes a link to `/profile/settings`.
- Resumes tab provides full CRUD management inline (list, create, edit, delete).
- Settings tab includes: duplicate-detection window, auto-fill toggle, auto-summary toggle.
- Identity tab is read-only (OAuth data).
- Work Preferences tab renders the existing preferences inline instead of a modal.

## Alternatives Considered

### B — Profile as landing + separate pages

Profile shows only Identity + Work Preferences. Settings and Resumes remain as independent routes (`/settings`, `/resumes`).

Rejected because it fragments the user's personal space across 3 separate pages and does not achieve the centralization the user requested. The sidebar "Resumes" item stays, increasing navigation clutter.

## Consequences

- **Positive:** Single destination for all user-related information. Sidebar becomes cleaner with one fewer nav item. The user card becomes functional instead of decorative. Spec 031 scope is absorbed and simplified — no separate `/settings` route needed.
- **Negative:** Profile page has higher complexity with 4 tabs. The Resumes tab must replicate the full list/detail/edit/delete flow that currently exists (or was planned) on the standalone `/resumes` page.
- **Neutral:** The `/resumes` route, if already implemented in part, will be removed or redirected to `/profile/resumes`.
