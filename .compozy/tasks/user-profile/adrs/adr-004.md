# ADR-004: Resumes Extraction and Route Migration

**Status:** Accepted
**Date:** 2026-05-23

## Context

Resume management currently lives at `/resumes` (list) and `/resumes/[id]` (detail/editor). The PRD moves this into the profile's Resumes tab at `/profile/resumes` and `/profile/resumes/[id]`.

The existing implementation is complete: `ResumesPage` (list + create + delete), `ResumeDetailsPage` (editor), `ResumeCard`, `AddResumeDialog`, `DeleteResumeDialog`, `ResumeTitleEditDialog`, and view-model hooks.

## Decision

**Remove the `/resumes` and `/resumes/[id]` routes entirely. Extract reusable content into shared components. Recreate routes under `/profile/resumes/`.**

1. Extract the list body (resume cards, dialogs, empty/loading/error states) from `ResumesPage` into a new `ResumesList` component that only renders content — no page chrome (no BackToLink, no action bar with its own layout).
2. Create `/profile/resumes/page.tsx` that renders the tab layout + `ResumesList`.
3. Create `/profile/resumes/[id]/page.tsx` that renders the resume detail/editor (reuses `ResumeDetailsPage` content).
4. Delete old route files at `/(authenticated)/resumes/page.tsx` and `/(authenticated)/resumes/[id]/page.tsx`.
5. Update `AddResumeDialog` to navigate to `/profile/resumes/[id]` after creation.

## Alternatives Considered

### A — Redirect old routes

Keep old routes redirecting to new ones. Rejected because it maintains dead code and creates confusion about the canonical URL. There are no external links to `/resumes` — only internal navigation from the sidebar (which is being removed).

### C — Copy and adapt

Duplicate the code into profile-specific components. Rejected because it creates divergent copies that will drift over time.

## Consequences

- **Positive:** Single source of truth for resume routes. No dead redirect code. Clean break from old URL structure.
- **Negative:** `ResumeDetailsPage` is tight to its current page structure and needs extraction of editor content from page chrome. The `BackToLink` in the detail page must point to `/profile/resumes` instead of `/resumes`.
- **Neutral:** Existing view-models and GraphQL hooks are reused unchanged.
