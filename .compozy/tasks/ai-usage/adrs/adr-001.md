# ADR-001: Provide an in-app OpenAI usage panel

## Status

Accepted

## Date

2026-08-20

## Context

Users need clear visibility into the tokens and calls consumed by Job Tracker. Usage must be distinguishable between a saved personal OpenAI key and the AI Trial.

## Decision

Provide an AI Usage subtab in Profile with two clearly separate areas. Personal OpenAI Key Usage and AI Trial Usage each report Job Tracker usage for the preceding 30 days: total, input, and output tokens plus calls. The AI Trial area also keeps the existing allowance, calls used, and calls remaining. The panel refreshes on entry and provides an explicit refresh control.

## Alternatives Considered

### Alternative 1: Account-wide provider usage

- **Description**: Query usage across the user's OpenAI account.
- **Pros**: Includes use outside Job Tracker.
- **Cons**: Requires administrative provider access and cannot reliably be attributed to the saved request key.
- **Why rejected**: The feature measures Job Tracker functionality usage, not the account's external activity.

### Alternative 2: A combined in-app total

- **Description**: Combine personal-key and AI Trial usage into one total.
- **Pros**: Reduces the number of displayed panels.
- **Cons**: Hides which funding source was used.
- **Why rejected**: Users need the two sources separated.

## Consequences

### Positive

- Users can monitor recent Job Tracker consumption for either source.
- The view distinguishes total, input, output, and call usage.
- Users can see trial token use without conflating it with personal-key usage.

### Negative

- Usage history starts at feature launch; it cannot reconstruct earlier requests.

### Risks

- Incomplete provider response usage must not be counted as a successful measured call.

## Implementation Notes

The implementation must never expose the saved key to the browser or log it. It must scope every result to the authenticated user and usage source.
