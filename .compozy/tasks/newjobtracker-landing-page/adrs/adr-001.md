# ADR-001: Landing page narrative structure and delivery approach

## Status

Accepted

## Date

2026-08-17

## Context

NewJobTracker needs a public marketing landing page. The product is a free, BYOK (bring-your-own-API-key) job application tracker with AI-assisted features (draft applications from a pasted link, AI fit scoring against a resume, pipeline tracking, salary/offer comparison). Sign-in is Google OAuth only; there is no publicly installable browser extension yet, and there is no pricing tier beyond BYOK.

Competitive research (Teal, Huntr, Simplify, Careerflow) shows most job-tracker landing pages open with a pain-point headline ("spreadsheet chaos"), then a feature grid, then a trust/pricing section. None of them foreground data privacy or AI-key ownership, despite BYOK being a real differentiator for a technical audience.

Three structural approaches were considered for the page, plus a decision on how the page gets delivered (mockup first vs. direct production route).

## Decision

Use a **product-flow narrative** structure: the hero opens with the real product loop in action (paste a link → AI draft → pipeline → fit score → offer comparison) as the visual thesis, rather than a pain-point headline. This is followed by a BYOK/privacy proof section ("your key, your data"), then the four existing feature messages (already validated in the LoginV2 UI copy) presented one at a time, ending on a single CTA: **Sign in with Google**.

Delivery: build the page first as a **standalone mockup (Claude Artifact)** to validate visual direction quickly, without touching production code. Only after visual approval does it get ported into a real Next.js route in `apps/web`.

## Alternatives Considered

- **Direct competitor-pattern structure** (pain point → feature grid → trust section → CTA): more familiar and lower-risk, but less distinctive; buries BYOK as a generic "trust" bullet instead of a lead differentiator; doesn't showcase the product loop, which is the most concrete thing NewJobTracker has to show.
- **Minimalist single-screen page** (headline + one visual + CTA): lowest effort and highest confidence via simplicity, but the product's AI loop and BYOK model both need enough explanation that a single screen risks under-communicating value to a technical but skeptical audience.
- **Build directly as a production Next.js route**: skips the mockup step and saves one round of porting, but risks committing design-system changes (new typography, layout patterns) to production code before the direction is validated with the user.

## Consequences

- The hero must visually or narratively demonstrate the product loop (link → draft → pipeline → fit → offer), which is more design work than a static headline but produces a more distinctive, product-grounded page.
- BYOK/privacy gets a dedicated section ahead of the feature grid, elevating it above where competitors typically place trust messaging.
- The extension is not mentioned anywhere on the page (not yet publicly installable).
- No pricing section is needed (product is free; BYOK covers the AI cost model).
- An extra porting step (mockup → real Next.js route) is required after visual approval, which is accepted as the cost of validating design direction cheaply first.
