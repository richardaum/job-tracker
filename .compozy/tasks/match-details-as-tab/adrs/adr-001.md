# ADR-001: Match as Dedicated Main-Column Tab

## Status

Accepted

## Date

2026-05-23

## Context

Match analysis (`MatchAnalysisPage`) currently lives as a standalone page at `/matches/[id]` with its own route, sidebar link, and list page (`/matches`). The job detail page (`/jobs/[id]`) already has an `OverviewTabContent` with a `MatchAnalysisField` summary, creating a disjointed experience — the user sees a match summary on the job but must navigate away to see full details.

The goal is to consolidate: make match details a first-class tab inside the job detail page, remove the standalone match routes, and redirect legacy URLs.

## Decision

Move match analysis into a **dedicated tab in the main column** of the job detail page, alongside Overview, Description, and Source content. The Match tab renders the full `MatchAnalysisPage` content (masonry grid with `MatchItemCard`s, verdict filters, status badge). Match-specific actions (Generate, Delete) live in a toolbar within the tab. The existing `MatchAnalysisField` summary remains in Overview. URLs: `/matches/[id]` permanently redirects to `/jobs/[id]/match`. The `/matches` list route is removed entirely; the sidebar "Matches" link is removed.

## Alternatives Considered

### Alternative 1: Match in Side Panel

- **Description**: Match tab replaces or joins Notes/History in the ActivitySidePanel (360px side column).
- **Pros**: Keeps main column focused on job content only. No tab bar crowding.
- **Cons**: Masonry grid at 360px is cramped — `MatchItemCard`s designed for wider layouts. Match content becomes secondary to job content (buried in side panel). Less visual weight for match analysis.
- **Why rejected**: The full match content (masonry grid, cards, filters) is designed for main-column width. Constraining it to 360px degrades usability significantly.

## Consequences

### Positive

- Single source of truth for match analysis — accessed from the job it belongs to
- No context switch between job detail and match detail pages
- Legacy URLs preserved via redirect, no broken links
- Cleaner sidebar with one fewer top-level navigation item
- Match gets full-width rendering in the main content area

### Negative

- Job detail TabsList grows by one trigger (from 3–4 to 4–5) — may feel crowded on narrow viewports
- Users lose the ability to browse all matches across jobs in a single list (`/matches`)
- Match actions toolbar adds a second level of UI chrome within the tab

### Risks

- Users accustomed to the standalone `/matches` list may be disoriented. **Mitigation**: the Overview tab retains `MatchAnalysisField` as a discoverable entry point with a link to the Match tab.

## Implementation Notes

- Match content extraction: `MatchAnalysisPage` content moves into a `MatchTabContent` component; page chrome (header, BackToLink) is removed since the job detail provides it.
- Route: `/jobs/[id]/match` renders `JobDetailsPage` with the Match tab pre-selected.
- Redirect: `/matches/[id]` → `/jobs/[id]/match` via Next.js `redirects()` with `permanent: true` (308).
- Match-specific actions (Generate, Delete) live in a toolbar at the top of the Match tab content, not in the job detail header.
