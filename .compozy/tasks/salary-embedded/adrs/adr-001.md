# ADR-001: SalaryEmbedded with validation via class-validator

**Status:** Accepted
**Date:** 2026-05-22

## Context

`JobEntity` currently has 4 flat salary columns (`salaryMinCents`, `salaryMaxCents`, `salaryCurrency`, `salaryPeriod`) that form a cohesive group. TypeORM supports embedded entities that map multiple columns into a single class. An embedded approach consolidates these 4 columns, reduces duplication, and aligns with the existing `AsyncMetadataEmbedded` pattern.

## Decision

**Create `SalaryEmbedded` as a TypeORM embedded class with `class-validator` decorators for validation.**

- The embedded class carries `@Column()` decorators for the 4 salary fields plus `class-validator` decorators (`@IsOptional`, `@Min`, `@Max`, `@Matches`, etc.).
- A `validate()` method performs cross-field validation (e.g., if any amount is set, currency and period are required; min ≤ max).
- `SalaryService` delegates validation to `embedded.validate()` instead of duplicating validation logic.
- Property name on `JobEntity`: `salary` (e.g. `job.salary.minCents`).
- DB prefix: `salary` → columns remain `salary_min_cents`, `salary_max_cents`, `salary_currency`, `salary_period` (no migration needed).
- `SalaryColumns` and `SalaryInput` types derive from the embedded shape.
- `SalaryResolver` uses the embedded to construct the `JobSalaryType` GraphQL type.

## Alternatives Considered

### A — Embedded mínimo (pure data class)

No validation on the embedded. `SalaryService` retains all validation. Rejected because it keeps validation dissociated from the data type and duplicates the field shape across multiple files.

### C — Embedded as full value object

Embedded with `normalize()`, `toGraphQL()`, `isEmpty()`, `toCents()` methods. Rejected because it overloads a data class with too many responsibilities, breaking SRP and deviating from the existing embedded pattern.

## Consequences

- **Positive:** Single source of truth for salary shape and validation rules. `SalaryService` becomes thinner. Validation logic is reusable outside NestJS context (e.g., scripts, tests).
- **Negative:** Adds `class-validator` dependency awareness to the embedded layer (already a project dependency). `SalaryService` must be refactored to delegate validation.
- **Neutral:** DB schema unchanged (no migration). All 4 column names preserved via TypeORM prefix.
