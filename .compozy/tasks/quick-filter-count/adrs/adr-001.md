# ADR-001: Static Count Badges for Quick Filters

## Status

Accepted

## Date

2026-07-25

## Context

The jobs list page has quick filter chips (All, Draft, Incoming, Active, Applied, New, Duplicated, Rejected) that let users filter the job list by pipeline stage. Currently, no count is displayed on any chip. Users have no visibility into how many jobs match each filter without clicking through. The request is to show counts on every quick filter tag.

Three questions were clarified:

- All filters should show counts
- Badges hide when count = 0
- Counts refresh on page load and after any mutation (create, delete, stage change)

## Decision

Implement static count badges on all quick filter chips. The badge renders inline in the FilterChip component, shows the count as a small number, and hides when count = 0. Filters keep their current fixed order and layout. Counts refresh via refetch after any mutation.

## Alternatives Considered

### Alternative 1: Dynamic Count Bar

- **Description**: Filters auto-sort by count descending, add a total counter header, and use differentiated visual weight for high vs low counts.
- **Pros**: More informative, highlights most populated categories, provides total job count.
- **Cons**: Changes expected filter order (disorienting), more visual changes across the filter bar, higher scope for MVP.
- **Why rejected**: The user values simplicity and predictability. The static approach fulfills the core need without rearranging the UI.

## Consequences

### Positive

- Users instantly see how many jobs match each filter category
- Simple, predictable UI — filters stay in expected positions
- Badge hidden at 0 reduces visual clutter

### Negative

- Does not auto-highlight the most populated categories
- No total job count in the filter area

### Risks

- Refetch after mutation may cause brief layout shift if not handled smoothly; mitigation: keep existing layout stable and show badge count as it loads
- No real-time updates — counts may be briefly stale until the next mutation or page load; acceptable per user preference
