# ADR-004: Centralized Frontend AI-Blocked Handling via Apollo Error Link

## Status

Accepted

## Date

2026-07-30

## Context

Nine frontend surfaces trigger AI-related GraphQL mutations/queries (chat, summary, auto-fill, match analysis, notes, company description, location inference, rewrite, restructure). Per the PRD, any of these must open a guidance modal — differentiating "AI turned off" from "no key/quota" — when blocked, linking to Settings. The TechSpec needs to decide where this response-handling logic lives on the frontend.

## Decision

Add a global Apollo error link that inspects `extensions.code` on GraphQL errors for the AI-specific codes (`AI_DISABLED_BY_USER`, `AI_KEY_REQUIRED` — see TechSpec API Design) and opens a shared `AiBlockedDialog` (built on the existing `packages/ui` `Dialog` component) with the appropriate message and a link to `/profile/settings`. Individual components that trigger AI mutations require no error-handling code for this case.

## Alternatives Considered

### Alternative 1: Per-component try/catch

- **Description**: Each of the 9 components catches its mutation's error and independently decides whether to show the modal.
- **Pros**: Keeps handling local to each component, no shared interceptor needed.
- **Cons**: Duplicates the same "check code, open dialog" logic 9 times; risks inconsistent wording or behavior drifting between surfaces over time; a new AI feature added later must remember to add the handling.
- **Why rejected**: Same rationale as ADR-003 on the backend — centralizing at the transport layer removes an entire class of per-feature omissions and keeps the "consistent AI-blocked experience" PRD requirement enforceable in one place.

## Consequences

### Positive

- New AI-triggering components automatically get correct blocked-state handling with zero added code, as long as they go through the shared Apollo client.
- One place to update copy, styling, or behavior of the blocked-state modal.

### Negative

- The error link needs a way to open a globally-mounted dialog from outside React's component tree (e.g., a small shared UI-state store or context reducer), a pattern not previously needed in this codebase.

### Risks

- A mutation that intentionally wants to handle the AI-blocked error differently (e.g., inline instead of a modal) would need an explicit opt-out mechanism. None of the 9 current entry points require this; flagged for future consideration if it arises.
