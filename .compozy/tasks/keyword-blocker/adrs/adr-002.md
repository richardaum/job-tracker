# ADR-002: Block on Creation Only — Short-Circuit Stage Assignment

**Status:** Accepted  
**Date:** 2026-05-27  
**Context:** When keyword matches a job, the job should be rejected. The question is whether blocking happens at creation time only or is re-evaluated reactively.

## Decision

Block at creation time only. Before persisting, the service checks title, description, and company against the user's blocked keywords. On match, the job is created with stage `REJECTED`. This is a short-circuit — the job is created but immediately in the rejected stage, not a retroactive filter.

## Alternatives Considered

### Reactive / always-on

Blocking is re-evaluated on every list query.  
_Pro:_ If user adds a keyword later, existing matching jobs automatically hide.  
_Con:_ Requires a join/filter on every jobs query; changes are unexpected — jobs the user was reviewing can disappear.

### Batch re-evaluation

A background job or migration to re-evaluate existing jobs when keyword list changes.  
_Con:_ Overengineering for v1; same UX surprise problem.

## Consequences

- Adding or removing keywords never retroactively changes existing jobs.
- User manually transitions blocked jobs out of REJECTED if desired.
- Quick filter for `REJECTED` stage (existing `ApplicationQuickFilter`) suffices to review blocked jobs.
- Simple datafix import: run once, create jobs already in REJECTED.
