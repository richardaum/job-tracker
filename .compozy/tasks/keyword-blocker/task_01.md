# Task 01: Data Model + Migration

## Overview

Add two JSONB columns (`blocked_keywords` and `blocked_companies`) to the `user_settings` table, create a TypeORM migration, and expose new GraphQL types (`BlockedKeywordType`, `KeywordScope`, `MatchMode` enums). Update `UserSettingType` and `UpdateSettingsInput` so the API surface is ready for the blocker service and settings UI.

<critical>
- Read PRD § Core Features 1 (Keyword Storage) and TechSpec § Data Models, § API Endpoints
- Reference TechSpec § "Build Order" step 1
- Focus on WHAT the data model must support, not HOW the blocker will use it
- Tests required for new types and migration
</critical>

<requirements>
- MUST add `blocked_keywords` JSONB column to `user_settings` with default `'[]'::jsonb`
- MUST add `blocked_companies` JSONB column to `user_settings` with default `'[]'::jsonb`
- MUST create a TypeORM migration file registered in `apps/api/src/database/migrations/index.ts`
- MUST define `KeywordScope` enum (`TITLE`, `DESCRIPTION`, `COMPANY`) with `registerEnumType`
- MUST define `MatchMode` enum (`PARTIAL`, `EXACT`) with `registerEnumType`
- MUST define `BlockedKeyword` GraphQL ObjectType with fields: `keyword`, `scope`, `matchMode`
- MUST define `BlockedKeywordInput` GraphQL InputType with fields: `keyword`, `scope`, `matchMode`
- MUST add `blockedKeywords` and `blockedCompanies` fields to `UserSettingType` (nullable, arrays)
- MUST add `blockedKeywords` and `blockedCompanies` fields to `UpdateSettingsInput` (optional, arrays)
- MUST NOT change existing settings fields or behavior
- MUST follow JSONB column patterns from backend/database.md § Async task JSONB metadata
- MUST register new migration in `apps/api/src/database/migrations/index.ts` (import + array entry)
</requirements>
