# ADR-002: Two-Phase Fill — Separate Extraction from Stage Transition

## Status

Accepted

## Date

2026-05-22

## Context

The PRD describes "Fill automatically" as a single action that extracts AI data and, when the job is in DRAFT stage, transitions it to NEW. However, extraction (AI call, data normalization) and stage transition (DRAFT → NEW, creating a stage event) are distinct operations with different failure modes and rollback semantics.

Extraction takes 5-15 seconds (async AI call) and may fail (AI timeout, malformed response). Stage transition is a synchronous DB update that creates a stage event. Coupling them in one mutation creates ambiguous partial-failure states: what if extraction succeeds but stage transition fails?

## Decision

**Separate "Fill automatically" into two GraphQL mutations**: `fillJobAutomatically(id)` and `advanceJobStage(id)`. The UI calls them sequentially after extraction completes, not as independent user actions. The fill status (IDLE → PROCESSING → COMPLETED/FAILED) is tracked via `fillMetadata` (AsyncMetadataEmbedded). The SSE stream emits fill status events so the frontend can react to completion and automatically trigger `advanceJobStage` when appropriate.

### fillJobAutomatically(jobId: ID!): JobType!

- Reads `htmlContent` (primary) or `urls` (fallback) as AI input source
- Returns immediately with `fillMetadata.status = PROCESSING`
- Background worker calls AI extraction, normalizes, and writes extracted fields to the same Job in-place
- On completion: sets `fillMetadata.status = COMPLETED`, emits SSE event
- On failure: sets `fillMetadata.status = FAILED`, sets `fillMetadata.error`

### advanceJobStage(id: ID!, justification: String): JobType! (existing mutation, extended)

- Already exists for other stage transitions
- Extended to accept DRAFT as a valid source stage

The frontend chains them:

1. User clicks "Fill automatically" → calls `fillJobAutomatically`
2. SSE event `fillCompleted` arrives → optionally auto-calls `advanceJobStage` (DRAFT → NEW)

## Alternatives Considered

### Alternative 1: Single mutation with implicit transition

- **Description**: One `fillJob(id)` mutation that extracts AND transitions DRAFT→NEW internally if stage is DRAFT.
- **Pros**: Simpler UI — one button, one API call. Matches the original PRD description more literally.
- **Cons**: Partial failure ambiguity (extraction succeeded but transition failed). Couples extraction logic with stage transition, violating SRP. Frontend has no hook point between extraction completion and stage change for custom UX.
- **Why rejected**: The coupling creates recoverability issues. Separating allows independent testing and clear failure boundaries.

### Alternative 2: Fill as a property of advanceJobStage

- **Description**: `advanceJobStage(id, DRAFT→NEW, fill=true)` — stage transition triggers fill internally.
- **Pros**: Single mutation from the user's perspective.
- **Cons**: Stage transition now has two radically different code paths (simple DB update vs async AI pipeline). Reverses the dependency direction (advanceStage depends on AI extraction).
- **Why rejected**: Introduces an unwanted dependency from stage management onto AI extraction.

## Consequences

### Positive

- Clear separation of concerns: extraction and stage management are independently testable
- Frontend can show intermediate state (fill in progress, then stage change) for better UX
- `advanceJobStage` mutation is reused without modification to its core logic (just enum extension)
- Extraction failures are isolated from stage management failures

### Negative

- Two mutation calls instead of one from the frontend perspective
- Frontend must implement chaining logic (trigger advanceStage after fill completes)
- Slightly more complex SSE handling (frontend listens for fill completion before triggering stage change)

### Risks

- **Frontend fails to chain correctly**: Mitigated by making the SSE-driven chain optional. Users can manually advance stage if auto-chain fails. The "Fill automatically" button remains available even after extraction completes but before stage transition.
