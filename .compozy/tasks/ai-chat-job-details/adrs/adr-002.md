# ADR-002: Dedicated AI Chat Tab in Side Panel (Supersedes ADR-001)

## Status

Accepted (Supersedes ADR-001)

## Date

2026-06-01

## Context

Initial approach (@ai mention in notes composer, ADR-001) was reviewed and reconsidered. The @ai approach mixes exploratory AI interactions with permanent notes, creating noise in the notes feed. Users would have 3+ AI notes per session that are not meaningful as permanent records.

A dedicated chat interface is cleaner: AI responses live in a conversation thread, not in the notes feed. Users can save individual responses to notes when relevant.

## Decision

Replace @ai mention approach with a dedicated "AI Chat" tab in the job details side panel:

1. Add "AI Chat" as a third side panel option (alongside Notes and History)
2. Users can create multiple conversations per job (named threads)
3. Each conversation has a persistent message history
4. AI responses stream into the chat interface
5. Individual AI messages can be saved as notes via a "Save as note" button
6. No @ai mention in the notes composer — no TipTalk mention extension needed
7. No changes to the notes data model (no `isAiGenerated` flag on notes)

## Alternatives Considered

### @ai mention in notes (ADR-001)

- **Description**: Type @ai in TipTap editor to ask AI, response posted as note
- **Pros**: Inline, no new UI, minimal new components
- **Cons**: Pollutes notes feed, poor discoverability, no follow-up conversation, requires TipTap extension
- **Why rejected**: ADR-001 actively rejected

### Dedicated AI Chat as a main tab

- **Description**: Add "AI Chat" as a primary tab (overview/description/source/match/chat)
- **Pros**: More visible, more space for chat
- **Cons**: Takes space from job content; chat fits naturally as a side panel interaction
- **Why rejected**: Side panel is the right place — chat is a supporting interaction, not primary content

## Consequences

### Positive

- Clean separation: AI exploration stays in chat, notes stay as permanent records
- Rich UX: streaming, follow-ups, conversation history
- Discoverable: "AI Chat" tab is obvious in the side panel
- No changes to TipTap editor or notes data model
- "Save as note" bridges the two systems intentionally

### Negative

- New data model needed (conversations + messages) — more backend work
- More UI surface area (conversation list, chat view, message components)
- Persistent storage means DB migration and new GraphQL operations

### Risks

- Users might not discover the feature if they don't open the side panel — mitigation: side panel is already used for notes/history
- Multiple conversations per job could get messy — mitigation: auto-title from first message, conversation list with search/delete

## Implementation Notes

- New entities: `ai_conversations`, `ai_messages`
- Migration: `CREATE TABLE` for both
- GraphQL: queries for conversations + messages, mutation to ask question, subscription for streaming
- Context: same as ADR-001 (full job context: title, description, company, match, notes, events)
- Reuse existing `AiBaseService` for AI calls
- Reuse existing EventBus + Subscription pattern for streaming
- "Save as note" calls existing `CreateJobNote` mutation
