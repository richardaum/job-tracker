# Worktree Env

**Explicit invocation only.** Follow this skill only when the user invokes `@worktree-env` (or `/worktree-env`) with `setup` or `teardown`. If they mention worktrees, ports, PM2, or `.env.worktree` without that invocation, do not read or apply this skill — answer from docs/rules or ask them to invoke the skill.

Run **api + web + storybook + extension** in this git worktree alongside the main checkout. One PM2 daemon on the host; isolation via ports, PostgreSQL database name, and PM2 name prefix.

## Invocation (required)

The user must invoke the skill by name and pass exactly one argument:

| Argument | Action |
| -------- | ------ |
| `setup` | Dry-run then `pnpm worktree:setup` with flags (no stdin) |
| `teardown` | Dry-run then `pnpm worktree:teardown -- --apply=true` (no stdin) |

Examples: `@worktree-env setup`, `/worktree-env teardown`.

If the skill was not invoked by name, or the argument is missing or not `setup` / `teardown`, stop. Ask the user to invoke again with `@worktree-env setup` or `@worktree-env teardown`. Do not run both flows in one invocation.

## Constraints

- **No tracked file edits** in the worktree (no `ecosystem.config.cjs` patch, no `apps/api/.env`, no `apps/web/.env.local`).
- Config is **only** root `.env.worktree` (gitignored), generated by `pnpm worktree:setup`.
- **Auth:** `AUTH_BYPASS_ENABLED=true` — no new Google OAuth redirect URIs.
- **DB clone:** requires `WORKTREE_SOURCE_DB` (env var or `--source-db=…`); secrets copied from main checkout `apps/api/.env`.
- **Flags only:** scripts never read stdin. Every boolean flag uses `=true` or `=false`. Teardown requires exactly one of `--dry-run=true` or `--apply=true`.
- **Dry-run first:** always dry-run before mutating, with the same flags you will use on the apply run (except flip `--dry-run` / `--apply`).
- If any step fails, stop and show the exact command + stderr. Do not improvise port/DB/PM2 fixes.
- `pnpm pm2:reset` / `pnpm ports:kill` without `PM2_RESET_PORTS` are **refused** inside a worktree (use values from `.env.worktree`).
- **DBeaver:** optional `--dbeaver=true` on setup (add) or teardown (remove). `--force-dbeaver=true` replaces an existing connection (requires `--dbeaver=true`). Uses `~/Library/DBeaverData/.../data-sources.json` on macOS unless `WORKTREE_DBEAVER_DATA_SOURCES` is set.
- **Linked worktree only:** do not run `git worktree add` or create checkout paths. If not already inside a linked worktree, stop and tell the user to `cd` into one first (`pnpm worktree:setup` / `teardown` refuse the main checkout).

## Prerequisite — confirm linked worktree

Run from the **worktree root** (both `setup` and `teardown`):

```bash
GIT_DIR_ABS="$(realpath "$(git rev-parse --git-dir)")"
GIT_COMMON_ABS="$(realpath "$(git rev-parse --git-common-dir)")"
if [ "$GIT_DIR_ABS" = "$GIT_COMMON_ABS" ]; then
  echo "main checkout — stop"
else
  echo "worktree: $(git rev-parse --show-toplevel)"
fi
```

If the output is `main checkout`, stop. Do not proceed and do not create a worktree from this skill.

## Setup flags (all boolean flags required)

| Flag | Effect |
| ---- | ------ |
| `--dry-run=true\|false` | `true`: print plan only (core + optional post-steps) |
| `--source-db=NAME` | Source DB to clone (or `WORKTREE_SOURCE_DB`) |
| `--recreate-db=true\|false` | `true`: drop and re-clone destination DB |
| `--dbeaver=true\|false` | `true`: add DBeaver connection |
| `--force-dbeaver=true\|false` | `true`: replace existing DBeaver connection for slug |
| `--install=true\|false` | `true`: `pnpm install` (after core setup) |
| `--migrate=true\|false` | `true`: `pnpm --filter @job-tracker/api run db:migrate` |
| `--start=true\|false` | `true`: `pnpm pm2:start` |
| `--verify=true\|false` | `true`: curl health checks (WXT failure is warning only) |

Post-step flags are ignored during `--dry-run=true` (only listed in the plan).

## `setup` flow

Run only when the invocation argument is `setup`.

1. **Source database**

   ```bash
   export WORKTREE_SOURCE_DB=job_tracker   # or your main dev DB name
   ```

1. **Dry-run** (mandatory; match flags for the apply run except `--dry-run`)

   ```bash
   pnpm worktree:setup -- \
     --dry-run=true \
     --recreate-db=false \
     --dbeaver=false \
     --force-dbeaver=false \
     --install=false \
     --migrate=false \
     --start=false \
     --verify=false \
     --source-db=job_tracker

   # full stack preview:
   pnpm worktree:setup -- \
     --dry-run=true \
     --recreate-db=false \
     --dbeaver=true \
     --force-dbeaver=false \
     --install=true \
     --migrate=true \
     --start=true \
     --verify=true \
     --source-db=job_tracker
   ```

   Confirm slug, ports, DB clone action, `.env.worktree` path, post-steps, and optional DBeaver. Stop if anything looks wrong.

1. **Apply core + optional post-steps** (same flags, `--dry-run=false`)

   ```bash
   pnpm worktree:setup -- \
     --dry-run=false \
     --recreate-db=false \
     --dbeaver=false \
     --force-dbeaver=false \
     --install=false \
     --migrate=false \
     --start=false \
     --verify=false \
     --source-db=job_tracker

   pnpm worktree:setup -- \
     --dry-run=false \
     --recreate-db=false \
     --dbeaver=false \
     --force-dbeaver=false \
     --install=true \
     --migrate=true \
     --start=true \
     --verify=true \
     --source-db=job_tracker
   ```

   Idempotent re-run: reuses port registry when free, skips DB clone if DB exists (unless `--recreate-db=true`), regenerates `.env.worktree`.

   After merging or resolving conflicts, check **migration file order** under `apps/api/src/database/migrations/` before `--migrate=true`. See `.agents/rules/repository-architecture.md`.

1. **Confirm main checkout** still works on its default ports (3100/3101/6006/3001).

## Teardown flags (all boolean flags required)

| Flag | Effect |
| ---- | ------ |
| `--dry-run=true\|false` | `true`: print plan only |
| `--apply=true\|false` | `true`: execute teardown |
| `--drop-db=true\|false` | `true`: drop `job_tracker_<slug>`; `false`: keep database |
| `--dbeaver=true\|false` | `true`: remove DBeaver connection |

Exactly one of `--dry-run` or `--apply` must be `true`. Order on apply: PM2 → DBeaver (if `--dbeaver=true`) → dropdb (if `--drop-db=true`) → registry → `.env.worktree`.

## `teardown` flow

Run only when the invocation argument is `teardown`. No interactive confirm — user intent is explicit via `--apply=true`.

1. **Dry-run** (mandatory)

   ```bash
   pnpm worktree:teardown -- \
     --dry-run=true \
     --apply=false \
     --drop-db=false \
     --dbeaver=true
   ```

1. **Apply** (same flags, flip dry-run/apply)

   ```bash
   pnpm worktree:teardown -- \
     --dry-run=false \
     --apply=true \
     --drop-db=false \
     --dbeaver=true
   ```

   Optional git cleanup (manual): `git worktree remove <path>`, `git branch -D <slug>`.
