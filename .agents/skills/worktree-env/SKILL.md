# Worktree Env

Run **api + web + storybook + extension** in this git worktree alongside the main checkout. One PM2 daemon on the host; isolation via ports, PostgreSQL database name, and PM2 name prefix.

Only act on explicit user request.

## Invocation (required)

The user must pass exactly one argument:

| Argument | Action |
| -------- | ------ |
| `setup` | Dry-run then `pnpm worktree:setup` with flags (no stdin) |
| `teardown` | Dry-run then `pnpm worktree:teardown -- --apply` (no stdin) |

Examples: `@worktree-env setup`, `@worktree-env teardown`.

If the argument is missing or not `setup` / `teardown`, stop and ask the user to invoke again with one of those values. Do not run both flows in one invocation.

## Constraints

- **No tracked file edits** in the worktree (no `ecosystem.config.cjs` patch, no `apps/api/.env`, no `apps/web/.env.local`).
- Config is **only** root `.env.worktree` (gitignored), generated by `pnpm worktree:setup`.
- **Auth:** `AUTH_BYPASS_ENABLED=true` — no new Google OAuth redirect URIs.
- **DB clone:** requires `WORKTREE_SOURCE_DB` (env var or `--source-db`); secrets copied from main checkout `apps/api/.env`.
- **Flags only:** scripts never read stdin. Teardown requires `--dry-run` or `--apply`.
- **Dry-run first:** always dry-run before mutating, with the same flags you will use on the apply run.
- If any step fails, stop and show the exact command + stderr. Do not improvise port/DB/PM2 fixes.
- `pnpm pm2:reset` / `pnpm ports:kill` without `PM2_RESET_PORTS` are **refused** inside a worktree (use values from `.env.worktree`).
- **DBeaver:** optional `--dbeaver` on setup (add) or teardown (remove). `--force-dbeaver` replaces an existing connection. Uses `~/Library/DBeaverData/.../data-sources.json` on macOS unless `WORKTREE_DBEAVER_DATA_SOURCES` is set.
- **Linked worktree only:** do not run `git worktree add` or create checkout paths. If not already inside a linked worktree, stop and tell the user to `cd` into one first (`pnpm worktree:setup` / `teardown` refuse the main checkout).

## Prerequisite — confirm linked worktree

Run from the **worktree root** (both `setup` and `teardown`):

```bash
GIT_DIR_ABS="$(realpath "$(git rev-parse --git-dir)")"
GIT_COMMON_ABS="$(realpath "$(git rev-parse --git-common-dir)")"
if [ "$GIT_DIR_ABS" = "$GIT_COMMON_ABS" ]; then
  echo "main checkout — stop"
else
  echo "worktree: $(git rev-parse --show-toplevel)"
fi
```

If the output is `main checkout`, stop. Do not proceed and do not create a worktree from this skill.

## Setup flags

| Flag | Effect |
| ---- | ------ |
| `--dry-run` | Print plan only (core + optional post-steps) |
| `--source-db=NAME` | Source DB to clone (or `WORKTREE_SOURCE_DB`) |
| `--recreate-db` | Drop and re-clone destination DB |
| `--dbeaver` | Add DBeaver connection |
| `--force-dbeaver` | Replace existing DBeaver connection for slug |
| `--install` | `pnpm install` (after core setup) |
| `--migrate` | `pnpm --filter @job-tracker/api run db:migrate` |
| `--start` | `pnpm pm2:start` |
| `--verify` | curl health checks (WXT failure is warning only) |
| `--all` | `--install --migrate --start --verify` |

Post-step flags are ignored during `--dry-run` (only listed in the plan).

## `setup` flow

Run only when the invocation argument is `setup`.

1. **Source database**

   ```bash
   export WORKTREE_SOURCE_DB=job_tracker   # or your main dev DB name
   ```

1. **Dry-run** (mandatory; match flags for the apply run)

   ```bash
   pnpm worktree:setup -- --dry-run --source-db job_tracker
   # full stack preview:
   pnpm worktree:setup -- --dry-run --all --dbeaver
   ```

   Confirm slug, ports, DB clone action, `.env.worktree` path, post-steps, and optional DBeaver. Stop if anything looks wrong.

1. **Apply core + optional post-steps** (same flags, without `--dry-run`)

   ```bash
   # env + ports + DB only:
   pnpm worktree:setup -- --source-db job_tracker

   # env + install + migrate + PM2 + smoke:
   pnpm worktree:setup -- --source-db job_tracker --all

   # with DBeaver:
   pnpm worktree:setup -- --source-db job_tracker --all --dbeaver
   ```

   Idempotent re-run: reuses port registry when free, skips DB clone if DB exists (unless `--recreate-db`), regenerates `.env.worktree`.

   After merging or resolving conflicts, check **migration file order** under `apps/api/src/database/migrations/` before `--migrate`. See `.agents/rules/repository-architecture.md`.

1. **Confirm main checkout** still works on its default ports (3100/3101/6006/3001).

## Teardown flags

| Flag | Effect |
| ---- | ------ |
| `--dry-run` | Print plan only (required mode if not applying) |
| `--apply` | Execute teardown (required mode if not dry-run) |
| `--keep-db` | Do not drop `job_tracker_<slug>` |
| `--drop-db` | Drop DB (default) |
| `--dbeaver` | Remove DBeaver connection |

Order on apply: PM2 → DBeaver (if flagged) → dropdb → registry → `.env.worktree`.

## `teardown` flow

Run only when the invocation argument is `teardown`. No interactive confirm — user intent is explicit via `--apply`.

1. **Dry-run** (mandatory)

   ```bash
   pnpm worktree:teardown -- --dry-run
   pnpm worktree:teardown -- --dry-run --keep-db --dbeaver
   ```

1. **Apply** (same flags, plus `--apply` instead of `--dry-run`)

   ```bash
   pnpm worktree:teardown -- --apply
   pnpm worktree:teardown -- --apply --keep-db --dbeaver
   ```

   Optional git cleanup (manual): `git worktree remove <path>`, `git branch -D <slug>`.
