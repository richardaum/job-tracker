# Worktree Env

Run **api + web + storybook + extension** in this git worktree alongside the main checkout. One PM2 daemon on the host; isolation via ports, PostgreSQL database name, and PM2 name prefix.

Only act on explicit user request.

## Invocation (required)

The user must pass exactly one argument:

| Argument | Action |
| -------- | ------ |
| `setup` | Dry-run then `pnpm worktree:setup`, install, migrations, `pnpm pm2:start`, smoke checks |
| `teardown` | Dry-run then `pnpm worktree:teardown` (only after user confirms teardown) |

Examples: `@worktree-env setup`, `@worktree-env teardown`.

If the argument is missing or not `setup` / `teardown`, stop and ask the user to invoke again with one of those values. Do not run both flows in one invocation.

## Constraints

- **No tracked file edits** in the worktree (no `ecosystem.config.cjs` patch, no `apps/api/.env`, no `apps/web/.env.local`).
- Config is **only** root `.env.worktree` (gitignored), generated by `pnpm worktree:setup`.
- **Auth:** `AUTH_BYPASS_ENABLED=true` — no new Google OAuth redirect URIs.
- **DB clone:** requires `WORKTREE_SOURCE_DB` (env var or `--source-db`); secrets copied from main checkout `apps/api/.env`.
- **Dry-run first:** always run dry-run before the mutating command for the chosen argument (`setup` → `worktree:setup -- --dry-run`; `teardown` → `worktree:teardown -- --dry-run`). Repeat dry-run with the same flags you plan to use (`--dbeaver`, `--recreate-db`, `--keep-db`, etc.).
- If any step fails, stop and show the exact command + stderr. Do not improvise port/DB/PM2 fixes.
- `pnpm pm2:reset` / `pnpm ports:kill` without `PM2_RESET_PORTS` are **refused** inside a worktree (use values from `.env.worktree`).
- **DBeaver:** optional `--dbeaver` on setup (add) or teardown (remove). Uses `~/Library/DBeaverData/.../data-sources.json` on macOS unless `WORKTREE_DBEAVER_DATA_SOURCES` is set.
- **Linked worktree only:** do not run `git worktree add` or create checkout paths. If not already inside a linked worktree, stop and tell the user to `cd` into one first (`pnpm worktree:setup` / `teardown` refuse the main checkout).

## Prerequisite — confirm linked worktree

Run from the **worktree root** (both `setup` and `teardown`):

```bash
GIT_DIR_ABS="$(realpath "$(git rev-parse --git-dir)")"
GIT_COMMON_ABS="$(realpath "$(git rev-parse --git-common-dir)")"
if [ "$GIT_DIR_ABS" = "$GIT_COMMON_ABS" ]; then
  echo "main checkout — stop"
else
  echo "worktree: $(git rev-parse --show-toplevel)"
fi
```

If the output is `main checkout`, stop. Do not proceed and do not create a worktree from this skill.

## `setup` flow

Run only when the invocation argument is `setup`. Do not hand-pick ports or write env files.

1. **Require source database name**

   ```bash
   export WORKTREE_SOURCE_DB=job_tracker   # or your main dev DB name
   ```

1. **Dry-run setup** (mandatory before writes)

   ```bash
   pnpm worktree:setup -- --dry-run
   # or: pnpm worktree:setup -- --dry-run --source-db job_tracker
   # match flags you will use next, e.g. -- --dry-run --dbeaver
   ```

   Confirm slug, ports, DB clone action, `.env.worktree` path, and optional DBeaver line. Stop if anything looks wrong.

1. **Generate `.env.worktree`** (same flags as dry-run, without `--dry-run`)

   ```bash
   pnpm worktree:setup
   # or: pnpm worktree:setup -- --source-db job_tracker
   # re-clone DB: pnpm worktree:setup -- --recreate-db
   # DBeaver: pnpm worktree:setup -- --dbeaver
   ```

   Idempotent re-run: reuses port registry when free, skips DB clone if DB exists, regenerates `.env.worktree`.

1. **Install deps** if needed

   ```bash
   pnpm install
   ```

1. **Migrations** (explicit — not run by `worktree:setup`)

   Run API migrations if schema may have drifted since the source DB was cloned.

   After merging or resolving conflicts, **migration file order** (timestamp prefixes under `apps/api/src/database/migrations/`) may no longer match the order those changes landed on `main`. Renumber or reorder files if needed so dependencies run in the correct sequence before applying migrations in this worktree. See `.agents/rules/repository-architecture.md`.

1. **Start all four apps**

   ```bash
   pnpm pm2:start
   ```

   PM2 reads `ecosystem.config.cjs`, which loads `.env.worktree` and prefixes app names (`<slug>-api`, …).

1. **Smoke verification**

   Replace `<slug>` with `PM2_APP_PREFIX` from `.env.worktree` (or basename of worktree path).

   ```bash
   set -a && source .env.worktree && set +a
   pm2 list
   curl -fsS "http://localhost:${API_PORT}/health"
   curl -fsS "http://localhost:${WEB_PORT}/" | head -n 1
   curl -fsS "http://localhost:${STORYBOOK_PORT}/" | head -n 1
   curl -fsS "http://localhost:${WXT_DEV_PORT}/" | head -n 1 || true
   pm2 logs "${PM2_APP_PREFIX}-api" --lines 30 --nostream
   ```

   - Confirm **main checkout** URLs still work on its ports (3100/3101/6006/3001 by default).
   - Auth bypass: hit a Google auth route or documented bypass flow — no GCP console changes.

## `teardown` flow

Run only when the invocation argument is `teardown`. Only after the user confirms they want teardown.

1. **Dry-run teardown** (mandatory)

   ```bash
   pnpm worktree:teardown -- --dry-run
   # match flags for the real run, e.g. -- --dry-run --keep-db --dbeaver
   ```

   Confirm PM2 app names, registry/env paths, dropdb vs `--keep-db`, and DBeaver removal.

1. **Run teardown** (same flags, without `--dry-run`)

   ```bash
   pnpm worktree:teardown                 # PM2 + registry + .env.worktree + dropdb job_tracker_<slug>
   pnpm worktree:teardown -- --keep-db    # preserve the clone database
   pnpm worktree:teardown -- --dbeaver    # also remove DBeaver connection for this slug
   ```

   Optional git cleanup (manual, outside this skill): `git worktree remove <path>`, `git branch -D <slug>`.
